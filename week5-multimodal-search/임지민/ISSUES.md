# 구현 중 막힌 점과 해결

## 1. MetaCLIP2 예제의 설정을 SigLIP에 그대로 쓸 수 없었다
원본은 MetaCLIP2, GPU용 FAISS, 1,280차원을 전제로 한다. 이번에는 CPU에서도 실행할 수 있어야 하며 다른 모델을 사용하므로 그 설정을 그대로 복사하면 벡터 차원과 실행 환경이 맞지 않는다.

**해결:** `faiss-cpu`를 사용하고 이미지 임베딩 배열의 `shape[1]`로 실제 차원을 읽었다. SigLIP 전처리기로 이미지·텍스트를 각각 처리하고, 텍스트에는 `padding="max_length"`, `max_length=64`를 명시했다. 두 종류의 벡터를 float32·L2 정규화하여 `IndexFlatIP`에 넣었다. 저장한 인덱스를 다시 읽은 뒤 이미지 벡터 5개로 자기 자신이 1위, 점수가 약 1인지 검증한다. 이 문제는 원본을 비교하며 발견한 **이식 시 차이점**이며, 차원 오류를 실제 발생시켰다고 주장하는 것은 아니다.

## 2. 기존 이미지 검색만으로는 캡션 정답 평가를 할 수 없었다
기존 앱은 업로드 이미지나 공개 저장소의 이미지를 모아 NumPy로 유사도를 계산했다. 사진 수백 장의 정답 캡션과 FAISS 저장 결과가 없어서 5주차 요구사항을 충족하지 못했다.

**해결:** 캡션 5개가 연결된 Flickr8k test에서 300장을 고정 추출했다. 사진 순서와 캡션을 `manifest.json`에 보존하고 같은 순서로 FAISS에 추가했다. 캡션은 이미지 임베딩에 섞지 않고 평가 질의로만 사용했다. `evaluation_details.json`에 모든 정답 ID와 Top 10 ID를 기록해 Recall@K를 다시 계산할 수 있게 했다. 한글 폴더에서는 인덱스를 바이트로 직렬화해 Python 파일 I/O로 저장한다.

## 발표할 때 설명
“기존 예제의 전체 흐름은 유지하되 모델을 SigLIP 2로 바꿨습니다. 모델이 바뀌면 임베딩 차원과 전처리도 달라져서 자동으로 차원을 읽고 정규화하도록 수정했습니다. 또 이미지 검색 결과가 좋아 보인다는 주관적인 판단을 넘어서, 사진에 연결된 캡션으로 1,500번 검색해 정답이 상위 K개 안에 들어오는 비율을 측정했습니다.”
