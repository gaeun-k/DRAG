# SigLIP으로 패션 이미지 검색하기 (FAISS + Recall@K)

**파이프라인**

1. Offline Indexing: 상품 이미지 → SigLIP 이미지 인코더 → 벡터 → FAISS 인덱스에 저장 (한 번만)
2. Online Inference: 텍스트 질의 → SigLIP 텍스트 인코더 → 질의 벡터
3. Similarity & Look-up: FAISS에서 질의 벡터와 가장 가까운 이미지 k장 검색 → 번호로 상품 정보 조회
4. 평가: Recall@K (상품명으로 검색 시 정답 사진이 상위 K장 안에 드는 비율) + 속성 기반 Precision@K (영어 vs 한국어)

**베이스 노트북에서 바꾼 점**

- 모델: metaclip -> siglip
- 데이터: 음식 사진 -> 패션 상품
- FAISS 인덱스: IndexFlatL2 -> IndexFlatIP
- 텍스트 입력: 기본 토크나이즈 -> padding='max_length'
- 임베딩: 이미지 한 장씩 -> 배치 단위 (64장씩)
- 인덱스: 거리 -> 내적

## 04. Recall@K: 상품명으로 검색했을 때 정답 사진이 상위 K장 안에 든 비율
- 질의: 각 상품의 상품명 (N_IMAGES개)
- 정답: 그 상품명의 원래 사진 (1장)
- Recall@K = 정답 사진이 상위 K장 안에 든 질의 수 / 전체 질의 수
- 랜덤 기대값: 아무렇게나 K장을 골랐을 때의 Recall (= K / 이미지 수). 이것과 비교하면 모델이 얼마나 잘하는지 알 수 있음

  <img width="492" height="130" alt="image" src="https://github.com/user-attachments/assets/ca0ce0db-5cab-4e87-9404-237f9fa22c73" />
- 랜덤 대비 크게 상승 - 모델이 확실히 작동함
- Recall@1->@10 상승 - 정답 근처까지는 찾지만, 비슷한 상품 사이에서 1등을 못 고름

  <img width="482" height="651" alt="스크린샷 2026-10-10 오후 1 45 28" src="https://github.com/user-attachments/assets/59d13448-7de2-40ac-a86c-42f31f876d0b" />
- 세 개 모두 색상·종류·성별은 맞음
- 실패 원인? 
  - 상품명이 이미지로 확인 불가능한 정보(브랜드, 모델 코드)에 의존
  - 구분 포인트가 너무 세밀하고 이미지 해상도가 낮음
  - 라벨·상품명보다 다른 상품이 시각적으로 질의에 더 맞음

## 막힌 점 

**데이터**
- 같은 상품명이 여러 개 -> 중복 상품 제외 후 600장 사용 (상품명 1개 = 정답 1장)
- 상품명에 브랜드·모델 코드처럼 이미지로 알 수 없는 정보가 많음 -> Recall@1이 낮은 원인
- 색상 라벨이 하나뿐 -> 여러 색이 섞인 상품은 맞아도 오답 처리
- 이미지 해상도가 작음 -> 세부 형태 구분 어려움
