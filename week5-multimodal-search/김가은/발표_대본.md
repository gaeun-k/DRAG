# 5주차 데모 공유 대본 — 텍스트 → 이미지 검색 (SigLIP + FAISS)

> 세션 ① "데모 공유 + 디버깅" 시간용, 약 5~6분. 슬라이드 없이 Colab 노트북 화면을 공유하면서 진행합니다.
> [ ] 안은 화면에서 할 동작입니다.

### 1. 무엇을 만들었나 (40초)
[노트북 맨 위 표 보여주기]

제가 만든 건 텍스트로 이미지를 찾는 검색 시스템입니다. 과제대로 smol-vision의 MetaCLIP2 이미지 검색 노트북을 베이스로 했고, 모델을 4주차에 배운 SigLIP으로 바꿨습니다.
한국어로도 검색하고 싶어서 다국어 모델인 siglip-base-patch16-256-multilingual을 썼고, 데이터는 Flickr8k에서 사진 500장을 가져왔습니다. 사진마다 영어 캡션이 5개씩 달려 있어서, 나중에 정확도를 잴 때 정답으로 썼습니다.

### 2. 흐름과 원본에서 바꾼 점 (1분)
[3번 셀: 인덱싱 코드와 "인덱스 완성: 500개 · 768차원 · 10초" 출력]

흐름은 원본 노트북과 똑같이 세 단계입니다. 먼저 사진 500장을 SigLIP 이미지 인코더에 넣어서 벡터로 바꾸고 FAISS에 저장합니다. 이건 한 번만 하면 되고, T4에서 10초 걸렸습니다. 그다음 질문이 들어오면 텍스트 인코더로 질문만 벡터로 바꾸고, FAISS에서 가장 가까운 사진을 찾습니다.

원본에서 바꾼 건 크게 네 가지입니다.
첫째, 텍스트를 넣을 때 padding="max_length"를 꼭 넣어야 합니다. 4주차에서 본 것처럼 SigLIP은 64토큰으로 맞춰서 학습했기 때문입니다.
둘째, 최신 transformers에서는 get_image_features 결과가 벡터가 아니라 객체로 나와서, pooler_output을 꺼내야 했습니다.
셋째, 인덱스는 원본의 IndexFlatL2 대신 IndexFlatIP를 썼습니다. 벡터를 정규화한 뒤 내적하면 바로 코사인 유사도가 돼서 점수가 클수록 비슷한 사진입니다. 참고로 이건 500개를 전부 비교하는 정확 검색이고, 데이터가 작아서 근사 검색까지는 안 썼습니다.
넷째, 4주차에서 배운 t와 b로 '짝일 확률'도 같이 계산해서, 관련 없는 사진을 걸러낼 수 있게 했습니다.

### 3. 검색 결과 (1분)
[4번 셀: 영어·한국어 검색 결과 그림]

영어로 "a dog running on the grass"를 검색하면 갈색 개가 달리는 사진이 1위로 나옵니다. 같은 뜻으로 "잔디밭에서 뛰는 강아지"라고 한국어로 검색해도 똑같은 사진이 1위로 나왔습니다. "바다에서 노는 아이들"도 해변에서 노는 아이들 사진을 잘 찾았습니다.

[5번 셀: 고양이 검색 결과]
재미있었던 건 "a cat sitting on a sofa"입니다. 이 500장에는 고양이 사진이 없는데, 결과 3장이 전부 짝일 확률 0%로 나와서 '관련 없음'으로 걸러졌습니다. 원본 노트북에서는 k장을 달라고 하면 관련 없는 사진도 섞여 나왔는데, SigLIP 확률로 그걸 거를 수 있었습니다. 그리고 인덱스를 파일로 저장해 두면 다시 불러와서 바로 검색할 수 있는 것도 확인했습니다.

### 4. 정확도: Recall@K (40초)
[6번 셀: Recall@K 출력]

정확도는 Recall@K로 쟀습니다. 캡션을 질문으로 넣었을 때 원래 사진이 상위 K장 안에 들어오는 비율입니다. 500장 기준으로 1위 안에 77%, 5위 안에 96%, 10위 안에 99%가 들어왔습니다.
4주차에 pipeline 점수가 달랐던 게 생각나서, 질문을 "This is a photo of ~"로 감싸서도 해 봤는데 차이가 1%p 정도로 거의 없었습니다. 문장 형식은 확률 값은 바꾸지만 순위에는 거의 영향이 없다는 걸 알 수 있었습니다.

### 5. 영어 vs 한국어, 영어 전용 vs 다국어 모델 (1분 30초)
[6-3번 셀: model_df 표]

마지막으로 한국어 질문에 정말 다국어 모델이 필요한지 비교했습니다. 영어 전용 모델로 같은 500장을 다시 인덱싱해서 비교했는데, 먼저 영어 Recall은 77.0%와 77.4%로 두 모델이 똑같았습니다.
한국어는 같은 뜻의 영어·한국어 질문 12쌍을 넣고 1위가 같은지를 봤는데, 두 모델 다 33%로 똑같이 나왔습니다. 숫자만 보면 차이가 없어 보입니다.

[6-3번 마지막 표: 한국어 질의별 1위 캡션]
그런데 한국어 질문의 1위 결과를 하나씩 직접 보니까 차이가 컸습니다. 다국어 모델은 12개 중 10개가 맞았고, 영어 전용 모델은 6개만 맞았습니다. 예를 들어 "암벽을 오르는 사람"을 영어 전용 모델에 넣으면 쇼핑백 든 남자가 나왔습니다.
지표에서 차이가 안 보인 이유는, 강아지나 해변 사진이 여러 장이라 한국어 질문이 영어와 '다른, 하지만 맞는 사진'을 찾아도 불일치로 셌기 때문입니다. 3주차 RAGAS 때처럼 지표만 보지 말고 결과를 직접 봐야 한다는 걸 다시 느꼈습니다.

### 6. 막힌 점 + 마무리 (40초)
막혔던 점은 두 가지입니다.
하나는 확률 기준값을 몇으로 잡을지입니다. 맞는 결과인데도 확률이 8%인 질문도 있고 97%인 질문도 있어서, 하나의 기준으로 거르기가 어려웠습니다.
다른 하나는 아까 말씀드린 것처럼, 한국어 정답 데이터가 없어서 영어·한국어 비교를 숫자로 깔끔하게 보여주기 어려웠던 점입니다.
그리고 "빨간 셔츠를 입은 남자"처럼 색이나 옷차림 조건은 두 모델 모두 틀려서, 이런 세부 조건에는 약하다는 것도 알게 됐습니다.

정리하면, 한국어 질문을 받을 6주차 챗봇에는 다국어 모델을 쓰는 게 맞고, 확률 기준값은 같이 정해 보면 좋겠습니다. 이상입니다.

**예상 질문 & 답변**
- **FAISS는 어디까지 썼나요?** → 인덱싱, 저장·불러오기, 검색을 FAISS로 했습니다. 500장이라 전부 비교하는 `IndexFlatIP`(정확 검색)를 썼고, HNSW 같은 근사 검색은 안 썼습니다.
- **Recall이 너무 높은 거 아닌가요?** → 후보가 500장뿐이고, 캡션이 그 사진을 직접 설명하는 문장이라 쉬운 편입니다. 사진이 수천 장으로 늘면 떨어질 겁니다.
- **영어 전용 모델이 한국어를 왜 조금 알아듣나요?** → 해변·눈·축구처럼 일부는 맞혔지만 이유는 확인하지 못했습니다. 절반 정도는 틀려서 한국어용으로 쓰기는 어렵습니다.
- **✓/✗ 판정은 어떻게 했나요?** → 1위 사진의 캡션을 보고 질문과 맞는지 판단했습니다.
