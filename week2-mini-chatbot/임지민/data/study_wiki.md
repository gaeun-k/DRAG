# RAG 스터디 운영 위키

이 문서는 미니 RAG 챗봇 실습을 위해 작성한 가상의 자체 위키입니다. 실제 학교나 기관의 규정이 아닙니다.

## 2주차 학습 목표
2주차 제목은 기본 RAG 파이프라인 구현입니다. 목표는 LangChain으로 기본 텍스트 RAG 파이프라인을 직접 구현하는 것입니다. 문서 청킹 전략, 프롬프트에 검색 결과를 결합하는 방식, 간단한 QA 챗봇 구현을 학습합니다.

## 과제와 제출물
각자 위키나 블로그 같은 자체 문서로 미니 RAG 챗봇을 구현합니다. 테디노트 GitHub 예제 코드를 수정해서 사용해도 됩니다. 제출물은 실행 가능한 코드, 사용한 원본 문서, 실행 방법, 질문과 답변 예시 3개입니다. 문서에 없는 질문 예시도 하나 포함합니다.

## 역할과 세션
역할 분담 없이 전원이 전체 파이프라인을 직접 구현합니다. 세션에서는 각자의 챗봇을 시연하고 디버깅과 이슈를 공유합니다. API 키는 공유하지 않습니다.

## 청킹 실험
기본 실험값은 chunk_size 1000자, chunk_overlap 100자, 검색 결과 개수 k 4개입니다. 비교 실험은 청크 크기 500자와 1500자, 겹침 0자와 100자로 진행합니다. 질문을 고정하고 관련 청크 검색 여부, 답변 근거, 응답 시간을 기록합니다.

## RAG 구성
문서 로드, 분할, 임베딩, 벡터 저장소 생성까지가 인덱싱입니다. 질문이 들어오면 질문 임베딩으로 관련 청크를 찾고, 검색된 본문과 질문을 프롬프트에 넣어 언어모델이 답변합니다. 임베딩 모델은 텍스트를 벡터로 바꾸고, 언어모델은 답변 문장을 생성합니다. FAISS는 벡터 검색에 사용합니다.

## 근거와 한계
답변에는 참고한 근거 번호를 붙입니다. 검색된 문서에 답이 없으면 제공된 문서에서 확인할 수 없다고 답합니다. 검색 유사도가 높다고 답이 반드시 들어 있는 것은 아닙니다. 원본 문서를 교체하거나 청킹 설정을 변경하면 인덱스를 다시 만듭니다.
