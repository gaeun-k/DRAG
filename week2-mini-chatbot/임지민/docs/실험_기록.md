## 청킹 비교

로컬 AI 모드에서 같은 문서와 질문을 유지하고 한 번에 설정 하나만 바꿉니다. 매번 인덱스를 다시 만드세요. 너무 짧은 문서에서는 차이가 작으므로 여러 절로 구성된 본인의 글을 사용해도 됩니다.

| 실험 | chunk_size | overlap | k | 청크 수 | 정답 근거 검색 여부 | 답변 근거 일치 여부 | 응답 시간 |
| --- | ---: | ---: | ---: | --- | --- | --- | --- |
| 기준 | 1000 | 100 | 4 | | | | |
| 작은 청크 | 500 | 100 | 4 | | | | |
| 큰 청크 | 1500 | 100 | 4 | | | | |
| 겹침 제거 | 1000 | 0 | 4 | | | | |
| 검색 범위 축소 | 1000 | 100 | 2 | | | | |

## 오류 원인 분리

1. 청크 미리보기에 필요한 원문이 없으면 **로드/분할 문제**입니다.
2. 청크에는 있지만 검색된 근거에 없으면 **검색 문제**입니다. 표현, k, 청크 크기를 비교합니다.
3. 검색 근거에 정답이 있는데 답변이 틀리면 **프롬프트/생성 문제**입니다.
4. 답변은 맞지만 번호가 틀리면 **인용 문제**입니다. LLM이 붙인 번호를 직접 확인합니다.
5. 예외가 발생하면 키·네트워크·모델 접근 권한·패키지 환경을 확인합니다.

## 제출 전

- [ ] 본인 문서와 문서 출처를 준비했다.
- [ ] 로컬 AI 모드에서 실제 생성형 QA를 실행했다.
- [ ] 문서 내 질문 3개와 문서 밖 질문을 확인했다.
- [ ] 답변과 검색된 근거가 일치하는지 확인했다.
- [ ] 청킹 조건을 바꿔 비교했다.
- [ ] API 키와 `.env`, `.venv`를 제출하지 않는다.
- [ ] 각 단계가 받는 입력과 반환값을 설명할 수 있다.
- [ ] 세션에서 공유할 오류 또는 개선점 한 가지를 기록했다.
