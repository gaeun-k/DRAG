## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 알약 정보 도우미 |
| 한 줄 설명 | 알약 사진 또는 증상을 입력하면 식약처 공식 정보를 근거로 일반의약품 정보를 안내하는 멀티모달 RAG 챗봇 |
| 대상 사용자 | 약 이름을 모르거나, 증상에 맞는 일반의약품 정보를 먼저 확인하고 싶은 일반 사용자 |
| 서비스 범위 | 낱알 식별 정보가 있는 국내 일반의약품(정제·캡슐 등) **2,744종** |
| 근거 자료 | 식약처 의약품 낱알식별정보, 식약처 의약품개요정보(e약은요) |
| 형태 | Gradio 웹앱 (Google Colab에서 실행, 공유 링크 제공) |
| 역할 | 김가은: 텍스트 RAG · 유연: 이미지 식별 |

### 사용자 시나리오

| 시나리오 | 흐름 |
| --- | --- |
| A. 약을 갖고 있는데 뭔지 모른다 | 사진 업로드 → 후보 3개 확인 → 실물과 비교해 선택 → 복용법·경고·주의사항 확인 → "공복에 먹어도 돼요?" 같은 추가 질문 |
| B. 증상에 맞는 약이 궁금하다 | "콧물이 나고 재채기가 계속 나와요" 입력(또는 증상 버튼) → 관련 일반의약품 2~3개와 공식 효능, 복용 전 확인할 점 |
| C. 위험한 증상이다 | "숨쉬기 힘들어요" 입력 → 약 추천 없이 병원·119 안내 |

## 2. 기능 명세

### F1. 사진으로 약 찾기 (탭 1)

| 단계 | 사용자 화면 | 시스템 처리 |
| --- | --- | --- |
| 1 | 사진 업로드 (알약·은박 포장·상자, HEIC 가능) | 회전 보정 후 RGB 변환 |
| 2 | "약 찾기" | VLM으로 제품명·각인·색·모양·알약 위치 추출 → SigLIP2 검색 → 점수 결합 |
| 3 | 후보 3개를 DB 사진 갤러리로 표시 | 사용자가 실물과 비교해 직접 선택 (자동 확정 없음) |
| 4 | "약 정보 보기" | 질문 없이 선택한 경우 LLM 없이 **고정 템플릿**(종류·복용법·경고·주의사항) 출력 |
| 5 | 추가 질문 입력 | 선택한 약의 청크를 근거로 LLM 답변 + 출처 |

### F2. 증상으로 약 찾기 (탭 2)

| 단계 | 사용자 화면 | 시스템 처리 |
| --- | --- | --- |
| 1 | 증상 버튼 6개 또는 자유 입력 | 두통·발열, 콧물·재채기, 소화불량, 기침·가래, 속쓰림, 설사 |
| 2 | — | 위험 증상 키워드 검사 → 해당하면 진료 안내 후 종료 |
| 3 | — | 하이브리드 검색 → 재정렬 → 중복 제거 → 상위 3개 약 |
| 4 | 답변 | 효능·복용법·주의사항·경고를 근거로 예시 2~3개 + "복용 전 확인" + 출처 |

### 공통 동작

| 동작 | 설명 |
| --- | --- |
| 출처 표시 | 답변에 실제로 이름이 나온 약만 `약 이름 [섹션·섹션]` 형태로 표시 |
| 면책 문구 | 화면 하단에 항상 표시 |
| 확신 낮음 표시 | 1등 후보에 각인·제품명 근거가 없으면(각인 점수 < 0.8) 확신이 낮다고 알림 |
| 범위 밖 안내 | 같은 이름의 액상·시럽 등 서비스 범위 밖 제형은 포함되어 있지 않다고 명시 |

## 4. 시스템 구성과 모듈 명세

### 4-1. 구성

| 계층 | 모듈 | 역할 |
| --- | --- | --- |
| 화면 | `src/app.py` | 기본 Gradio 데모, 이벤트 핸들러(`on_identify`, `on_show_info`, `on_chat`, `on_reset`) |
| 화면 | `src/app_eun_final.py` | 탭 구조 최종 디자인 (`app.py`의 핸들러를 그대로 사용) |
| 화면 | `src/app_yeon.py` | 대체 디자인 (단독 실행) |
| 이미지 식별 | `src/identify.py` | VLM 추출 + SigLIP2/FAISS 검색 + 점수 결합 |
| 텍스트 RAG | `src/rag.py` | 청킹, 하이브리드 검색, 재정렬, 질문 분기, 답변 생성 |
| 데이터 준비 | `data_prep/fetch_eyak.py` | e약은요 API 전체 수집 |
| 데이터 준비 | `data_prep/build_master.py` | 조인·필터로 마스터 테이블 생성 |

### 4-2. 공개 함수

**`identify`**

| 함수 | 입력 | 출력 |
| --- | --- | --- |
| `load(base_dir)` | 마스터·인덱스가 있는 폴더 | 앱 시작 시 한 번 호출 (마스터, SigLIP2, FAISS, VLM 로드) |
| `identify(image, k=3, return_debug=False)` | 경로 / PIL 이미지 / 업로드 파일 | `[{"item_seq", "name", "image_url", "score"}, ...]` (점수 높은 순) |

**`rag`**

| 함수 | 입력 | 출력 |
| --- | --- | --- |
| `load(base_dir, use_dense=True, use_rerank=None)` | 마스터·청크가 있는 폴더 | 검색기 준비 (청크 파일이 없으면 자동 생성) |
| `search(question=None, item_seq=None)` | 질문, 선택한 약 코드(선택) | `{"answer": str, "sources": [{"item_seq", "name", "section"}]}` |

`identify`와 `rag`는 `item_seq`로 연결됩니다: `identify.identify(image)` → 사용자 선택 → `rag.search(question, item_seq=...)`.

## 5. 알고리즘 명세

### 5-1. 사진 식별 (`identify.py`)

1. **VLM 추출**: 사진 → `{product_name, imprints, color, shape, box_2d}` (JSON, temperature 0). 색·모양은 DB에 존재하는 값 중에서만 고르게 하고, 후처리에서 영어·중국어 응답도 한글 값으로 정규화.
2. **SigLIP2 검색**: 전체 사진과 `box_2d`로 자른 크롭을 각각 임베딩해 FAISS에서 벡터 150개 검색 → 약 단위로 최고 점수 → 상위 50개.
3. **후보 풀**: SigLIP 후보 ∪ 각인 유사도 ≥ 0.6 ∪ 제품명 유사도 ≥ 0.85.
4. **점수 결합**

   | 요소 | 계산 | 가중치 |
   | --- | --- | --- |
   | 각인 | 정규화한 각인 문자열 유사도(RapidFuzz `ratio`), 앞·뒤 중 최대 | 0.6 |
   | 이미지 | SigLIP 코사인 유사도를 후보군 안에서 min-max 정규화 | 0.2 |
   | 색 · 모양 | 일치 1점, 인접 값(예: 갈색↔빨강, 원형↔타원형) 0.5점의 평균 | 0.2 |
   | 제품명 | 포장 제품명 유사도 ≥ 0.85이면 유사도만큼 가산 | 보너스 1.0× |

5. **예외 처리**: 각인을 못 읽으면 각인 가중치를 이미지에 합산. VLM이 실패하면 SigLIP 점수만 사용.

### 5-2. 증상 검색 (`rag.py`)

| 단계 | 내용 |
| --- | --- |
| 대상 | 효능 청크 2,738개 |
| BM25 | Kiwi 형태소 분석에서 명사·동사·형용사·어근·외국어·숫자만 토큰화 |
| Dense | `BAAI/bge-m3` 임베딩, 정규화 후 내적 (효능 임베딩은 `efficacy_emb.npz`에 캐시) |
| 결합 | 가중 RRF: BM25 0.5 : Dense 1.0, k=60, 각 상위 30개 |
| 재정렬 | 약 단위로 중복을 제거한 상위 40개를 `bge-reranker-v2-m3`(CrossEncoder, max_length 512)로 재정렬 |
| 중복 제거 | 같은 약은 1번, 효능 토큰 집합 Jaccard ≥ 0.85인 약은 건너뜀 → 상위 3개 약 |

### 5-3. 질문 분기 (`rag.search`)

| 조건 | 모드 | 동작 |
| --- | --- | --- |
| 질문이 비어 있고 약만 선택 | 템플릿 | LLM 없이 종류·복용법·경고·주의사항 출력 |
| 위험 증상 키워드 포함 | 안내 | 약 추천 없이 진료·119 안내 |
| 질문 속 약 이름 인식(브랜드 줄기 매칭) | item | 해당 약의 모든 섹션을 근거로 답변 + 범위 안내 |
| 약 선택 + 약에 대한 질문(복용·식전·임신·병용 등 단서) | item | 선택한 약(병용이면 언급된 약도 함께)의 청크 사용 |
| 약 선택 + 무관한 증상 질문 | symptom | 증상 검색으로 전환하고 "선택한 약이 아니라 증상 기준"이라고 알림 |
| 그 외 | symptom | 5-2의 증상 검색 |

### 5-4. 답변 생성

- 모델 `gemini-flash-latest` (실패 시 `gemini-flash-lite-latest`), temperature 0.2, 모델당 3회 재시도(404/403은 즉시 다음 모델).
- 근거 섹션: item 모드는 전체, symptom 모드는 효능·복용법·주의사항·경고.
- 프롬프트 규칙: 자료에 있는 내용만 사용, 없으면 "제공된 정보에는 없어요", 진단·처방 말투 금지, 제형이 다른 제품은 제품별 분리, 증상 질문은 예시로만 제시하고 "복용 전 확인" 추가.
- 생성에 실패하면 식약처 원문을 그대로 출력.

큰 파일은 저장소에 없으므로 아래를 따로 준비해야 합니다.

| 필요한 것 | 준비 방법 |
| --- | --- |
| 낱알식별정보 `pill_info.csv` | 공공데이터포털에서 내려받아 `data_prep/`에 배치 |

| `assets/bg.jpg`, `assets/icon1.png` | `app_eun_final.py`의 배경·아이콘 (없으면 💊 이모지로 대체) |
